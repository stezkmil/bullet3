VBD GPU backend (Windows x64)

The main Bullet build enables BUILD_VBD_GPU by default. Runtime CPU fallback
remains available when the DLL or compatible NVIDIA driver/GPU is absent.

Standalone GitHub checkout
-------------------------
Install Visual Studio C++ tools, CMake 3.24+ and CUDA Toolkit 11.7+ including
NVRTC. No Conan packages or Python kernel-compilation script are required.
These prerequisites cover the GPU target. Building the full Bullet fork also
requires its existing oneTBB headers and libraries to be configured.
From the repository root, for example:

cmake -S . -B build -DCMAKE_CXX_STANDARD=20 -DBUILD_BULLET2_DEMOS=OFF -DBUILD_OPENGL3_DEMOS=OFF -DBUILD_CPU_DEMOS=OFF -DBUILD_EXTRAS=OFF
cmake --build build --config Release --target BulletVbdGpu

With CMake 4, also pass -DCMAKE_POLICY_VERSION_MINIMUM=3.5 to accommodate
the older minimum versions in the upstream Bullet CMake files.

CUDAToolkit_ROOT can select a specific installed toolkit. The backend is built
at build/bin/Release/BulletVbdGpu.dll. Place it beside the application executable.
The local PTX compiler and NVRTC DLLs are build tools and are not deployed.
A compatible NVIDIA driver is required at runtime; newer toolkit versions may
require newer drivers to load the PTX they generate.

For CPU-only builds, set -DBUILD_VBD_GPU=OFF; CUDA is then not searched for.
The GPU backend is currently Windows-only; disable it on other platforms.

Conan / VRUT
------------
The Bullet recipe supplies CUDA::cuda_driver and VBD_PTX_COMPILER using pinned
Conan packages. An explicit compiler path selects this mode and errors if it
is missing, rather than silently choosing a system toolkit.
The compiler source is also packaged in recipes/vrut-vbd-ptx-compiler: keep the
standalone copy and that package source synchronized when updating the tool.
